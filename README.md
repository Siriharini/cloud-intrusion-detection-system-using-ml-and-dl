# cloud-intrusion-detection-system-using-ml-and-dl
Cloud-IDS is an advanced intrusion detection system achieving a 99.27% F1-score on the NSL-KDD dataset. It utilizes a hybrid deep learning ensemble (1D-CNN + GRU + Transformer) with weighted risk synthesis to detect DoS, Probe, R2L, and U2R attacks. Features a stratified 80/20 data split and a live dashboard for real-time network mitigation.
Step 1: Dataset Acquisition & Feature SelectionCode Implementation: Section 1 (KDDTrain+.arff parser)How It Works: The system opens the raw .arff dataset, bypasses the metadata attributes via the @data marker split, and loads the streaming connections into a pandas DataFrame. It targets 41 features (like protocol type, service, and connection flags) to act as the primary structural input signature.
Step 2: Preprocessing & Data Transformation PipelineCode Implementation: Section 2 (LabelEncoder & MinMaxScaler)How It Works:
* Categorical Encoding: Non-numeric variables at indices [1, 2, 3] are converted to discrete integers using LabelEncoder.Dual-Target Labeling: The network creates two separate prediction profiles: a binary classification profile (y_bin) mapping records into normal ($0$) or attack ($1$), and a multi-class classification profile (y_poly) mapping records to specific granular attack signatures (e.g., Neptune, Satan, Smurf).Normalization: All numerical inputs are scaled between $0$ and $1$ using MinMaxScaler to stabilize gradient descent during the training of the neural networks.
Step 3: Stratified Dataset PartitioningCode Implementation: Section 3 (train_test_split(..., stratify=y_bin))How It Works: The feature space is divided into a strict 80% Training / 20% Testing balance. By enforcing the stratify=y_bin parameter, the system guarantees that the mathematically disproportionate distribution of normal vs. attack variants matches perfectly between your training and testing matrices, avoiding evaluation bias.
Step 4: Multi-Tier Parallel Ensemble EnginesCode Implementation: Section 4 (RandomForest, Sequential, Model)How It Works: The data is processed concurrently by independent defensive models to generate localized risk scores:Machine Learning Engine: A RandomForestClassifier creates an ensemble of decision trees to determine fundamental feature thresholds.Spatial Feature Tier (1D-CNN): A Conv1D convolutional layer acts as a signature extractor to isolate spatial anomalies across adjacent packet descriptors.Temporal Sequence Tier (GRU/RNN): A GRU layer tracks packet sequences over time to identify slow, multi-stage network attacks.Global Self-Attention Tier (Transformer): A custom MultiHeadAttention structure weights relationships across non-adjacent features to isolate complex structural exploits.Unsupervised Baseline Tier (Autoencoder): Trained strictly on clean traffic (y_train_bin == 0), this network maps the reconstruction error (ae_err). High reconstruction errors point directly to zero-day anomaly behaviors.
Step 5: Algorithmic Trust Score SynthesisCode Implementation: Section 6 (Dashboard scoring logic)How It Works: Instead of choosing a single model outcome, the system evaluates and aggregates all model weights using a custom integration algorithm:$$\text{Trust Score} = \text{Clip}(\text{RNN\_Risk} \times 0.2 + \text{GRU\_Risk} \times 0.5 + \text{Autoencoder\_Error} \times 8 + \text{ML\_Anomaly\_Bonus})$$This integration neutralizes individual model error rates, resulting in your final verified 99.27% F1-score.
Step 6: Dashboard Threat Mapping & Prioritized AlertingCode Implementation: Section 6 & 7 (Dashboard Simulation & matplotlib matrix)How It Works:Granular Identification: If an anomaly is identified, the system runs a reverse transformation using poly_encoder.inverse_transform to decode the neural index back to its literal uppercase string name (e.g., NEPTUNE, SATAN).Tri-Tier Alert Priorities: Connection instances are classified instantly into clear priority tiers:🚨 CRITICAL: Triggers when the combined Trust Score exceeds 0.35 or the Autoencoder Reconstruction Error exceeds 0.04.
⚠️ WARNING: Triggers when the Trust Score sits between 0.15 and 0.35.
✅ SECURE: Triggers for verified normal profiles maintaining low risk evaluations across all model blocks.
